# The plan

`design.md` says what Aerenfall is. This says how it gets built, in what order,
and which files each step is expected to touch. Milestones run in order. Each
one ends with the build loop run to a pass, the headless checks green, the web
export building, `CLAUDE.md` updated, and a summary of how to try the new thing.

## The build loop

No feature is done when it is written. Every feature goes round this until it
passes:

1. **Build** the smallest version that can be played.
2. **Test.** Run the headless checks. Fix failures before going on.
3. **Play.** Export the web build, drive it in a real browser with Playwright,
   scripted keyboard and mouse. Scripts live in `tests/playtest/` so they can be
   re-run later.
4. **Look.** Screenshot each key moment plus a burst of frames while moving.
   Actually open the images and look at them. Read the browser console. Log fps.
5. **Judge.** Write down what works and what does not, under four headings:
   bugs, feel, readability, fun. "It runs" is not "it works".
6. **Fix** the most important problems, then back to 2.

Rules for the loop: the log lives in `docs/playtest-log.md`, one entry per round
with the date, what was played, the screenshots, findings and changes. Stop when
the feature meets its goal and the last round found nothing important. **Five
rounds on the same problem without progress means stop and escalate.** Every bug
found in a playtest also gets a headless check, so it cannot come back quietly.

### Groundwork the loop needs

This has to exist before milestone 2's loop can run, and is part of milestone 2:

| Piece | Where | What it does |
| --- | --- | --- |
| Debug overlay | `scripts/debug_overlay.gd`, `scenes/ui/debug_overlay.tscn` | F3 toggles fps, player position, chunk, biome, Abyss layer, clock, nearest creature state. Makes a screenshot judgeable |
| Boot config | `scripts/boot_config.gd` | Seed, spawn position and starting inventory from `OS.get_cmdline_args()` on desktop and the URL query string on web, so a play script jumps straight to what it tests |
| Playtest harness | `tests/playtest/` | Static server over `build/web`, Playwright driver, screenshot helpers, console capture, fps sampling |

The web preset has `variant/thread_support=false`, so the export needs no
cross-origin isolation headers and a plain static file server is enough.

## Milestone 2 — the tile world

The big one. World generation, chunk streaming, digging, placing, lighting,
save and load, at 60 fps in the browser.

### Tasks

1. **Tile data model.** Tile ids, hardness, whether it collides, which layer it
   draws to. Data-driven from the start.
2. **Chunk store.** The world as byte arrays, chunk lookup, dirty flags, the
   deterministic per-chunk generator entry point.
3. **Generation.** Surface height by noise, biome bands across x, underground
   and cavern layers, caves, ore placement, the Abyss shaft near the middle,
   sky islands above the mountains.
4. **Structure stamps.** Load a text map from `levels/structures/` and stamp it
   into the world at a deterministically chosen site. Reuses the legend rules
   already in `tools/gen_levels.py`.
5. **Streaming.** Build and free tilemaps and collision for chunks near the
   camera. Pool the nodes; do not allocate per chunk per frame.
6. **Dig and place.** Mouse targeting inside a reach radius, break time from
   hardness and tool tier, block placement, the tile-changed signal that marks
   light and physics dirty.
7. **Lighting.** Per-tile light, flood fill from sky and sources, low-resolution
   darkness texture over the world, dirty-region recompute, work spread across
   frames under a budget.
8. **Water.** Cellular settling per tile in active chunks only.
9. **Save and load.** Seed plus per-chunk tile diffs under `user://`.
10. **Autotiling.** Tiles blend with their neighbours. Needs a bitmask tile set
    generated by `tools/gen_art.py` and terrain data in the tile set resource —
    the current 6-tile atlas has no terrain information at all.
11. **Move the legacy zones.** `levels/*.txt` to `levels/legacy/`, update the
    three zone scenes, point the title screen at the generated world.

### Checks to add

- The same seed twice produces identical chunk bytes; a different seed does not.
- A chunk generated in isolation matches the same chunk generated after its
  neighbours, which is what proves generation order does not matter.
- A dug tile is still dug after save, quit and load.
- Digging a tile updates collision, so the player falls through the hole.
- Light falls off with depth, and a torch raises light in a dark chunk.
- Water poured into a hollow settles level and stops.
- The Abyss shaft exists, is continuous, and is reachable from the surface.
- Every biome named in `data/` actually appears in a default world.

### Done when

A new world boots in under two seconds, the player digs, places and is lit by
their own torch, the world survives a save and reload, and the web build holds
60 fps while moving. Failing 60 fps, the honest number gets reported rather
than the target.

### Risks

**Lighting is the one to watch.** A per-tile flood fill in GDScript across a
streaming world is the most likely thing to miss frame budget in the browser.
Mitigations in order of preference: recompute only dirty regions, cap the work
per frame, drop the light grid below one cell per tile, and only then consider
moving the fill to a shader. If it cannot hit budget, that is a finding for the
milestone summary, not something to quietly ship at 30 fps.

**Autotiling is more work than it looks.** It touches the generator, the tile
set resource and every tile the world draws, and the current tile set has no
terrain data whatsoever.

## Milestone 3 — items and crafting

Inventory, hotbar, drops, ores, tool tiers, stations, data-driven recipes, and
the first armour.

- Item definitions, stack limits, an inventory model separate from its UI.
- Hotbar on 1 to 0, an inventory screen, both usable without a mouse hover so a
  mobile port stays possible.
- Dropped items that fly to the player and merge into stacks.
- Ore tiles that drop materials; smelting; tool tiers that change break time.
- Stations — workbench, furnace, anvil — with a proximity check.
- Recipes as data, resolved against nearby stations.
- First armour set and the damage reduction it implies.

Files: `scripts/items/*.gd`, `scripts/ui/inventory.gd`, `scripts/ui/hotbar.gd`,
`data/items.json`, `data/recipes.json`, `data/tiles.json`, `scenes/ui/*`,
`tools/gen_art.py` for item icons, `tests/`.

Checks: a recipe fails without its station and succeeds with it; stacks respect
their limit; a mined ore yields its drop; a better tool breaks a tile faster;
inventory survives save and load.

## Milestone 4 — creatures and companions

The heart of the game. Clock, schedules, Bestiary, trust, eggs, companions.

- The day clock, ~20 real minutes, with sky colour and light following it.
- Species definitions in `data/creatures/`.
- Creature AI: habitat spawning, nests and dens, schedules, temperament,
  line of sight and a fear response.
- Observation: unseen proximity fills the Bestiary in stages.
- Trust: right hour, right food, staged approach, decay when frightened.
- Eggs: theft while the parent is away, hostility if seen, incubation, rearing.
- Companion select, mount mode and rider mode, bond level.
- Ship three species: **wolf** (mount, fast run and pounce), **rabbit** (rider,
  higher jump and faster digging), **glowbug** (rider, light).

Files: `scripts/creatures/*.gd`, `scripts/clock.gd`, `scripts/bestiary.gd`,
`scripts/companion.gd`, `data/creatures/*.json`, `scenes/actors/*`,
`scenes/ui/bestiary.tscn`, `tools/gen_art.py`, `tests/`.

Checks: feeding at the right hour raises trust and at the wrong hour does not;
being seen taking an egg makes the parent hostile; scaring a creature costs
trust; a mounted wolf moves faster than the player on foot; a shouldered rabbit
jumps higher; the Bestiary reveals in the right order; schedules fire at the
right clock time.

## Milestone 5 — gating

The first real proof that "you unlock possibilities, not areas" works.

- Ocean at both map edges, with water deep enough to drown in.
- Oxygen meter underwater; the oxygen kit that extends it.
- A swimming companion.
- Snow biome cold, health drain, and the warm coat that stops it.
- A hippogriff nest on a mountain with an egg that can be stolen, and flight
  that reaches a sky island.

Files: `scripts/world/water.gd`, `scripts/player_survival.gd`,
`data/items.json`, `data/creatures/*.json`, `scripts/creatures/*.gd`, `tests/`.

Checks: unequipped players drown and equipped ones do not; cold drains health
without a coat and does not with one; a sky island is unreachable on foot and
reachable mounted; every gate in the table in `design.md` has a test.

## Milestone 6 — the Abyss, layers 1 to 5

- Five distinct layers: tiles, backdrop, light colour, creatures, danger.
- Layer readout on the HUD.
- Pressure as the deep-layer gate, and the suit that answers it.
- The climb back made costly in time and supplies.
- Outpost beacons: craft, place, and travel to from the surface camp.

Files: `scripts/world/abyss.gd`, `scripts/world/world_gen.gd`,
`data/abyss_layers.json`, `scripts/beacon.gd`, `scenes/ui/hud.tscn`,
`tools/gen_art.py`, `tests/`.

Checks: each layer generates with its own tile set and creatures; the HUD layer
number matches actual depth; a placed beacon survives save and load and travel
arrives at it; the deep layers punish an unsuited player.

## Milestone 7 — town and classes

- NPCs with a job, a home and a schedule on the day clock.
- A housing validity check, Terraria-style: enclosed, lit, furnished.
- A merchant who buys and sells.
- Class select at the start: Warrior, Ranger, Rogue, Arcanist, Beastmaster.
- A first skill tree per class, and cross-tree unlocks later.

Files: `scripts/npc/*.gd`, `scripts/housing.gd`, `scripts/classes.gd`,
`data/npcs.json`, `data/classes.json`, `scenes/ui/*`, `tests/`.

Checks: an invalid house is rejected and a valid one accepted; an NPC moves in
when its condition is met; buying and selling moves items and currency both
ways; each class starts with its kit; a skill unlock changes a real value.

## Standing rules

Carried from `CLAUDE.md` and `CONTRIBUTING.md`, repeated because this plan will
be read on its own:

- The existing 39 checks keep passing. Every new system adds checks.
- Never commit to `main`. Branch, push, open a pull request, keep CI green.
- Design owns `assets/`, `levels/` and `data/`. Code owns `scripts/`, `tests/`
  and `tools/`.
- Art is generated by `tools/gen_art.py`; CI fails if `assets/` drifts from it.
- Non-resource files only reach the exported build if `include_filter` names
  them. Every new data format gets added and then *verified in the export*.
- Input stays behind Godot input actions, and UI stays usable without hover.
- Small commits, one feature each, present-tense one-line messages.
- Nothing gets deleted without asking.

## Known repo facts worth carrying

Found while reading the repo, relevant to the work ahead:

- `project.godot` declares `config/features=PackedStringArray("4.7", ...)` while
  CI pins Godot 4.6 and the shipped build reports 4.6. Harmless so far, worth
  reconciling before it becomes a confusing failure.
- The tile set has six tiles in a single row and no terrain sets, so autotiling
  starts from nothing.
- `include_filter` is currently `levels/*.txt` only. Moving maps into
  `levels/legacy/` and adding `data/` both depend on this being widened and
  checked in the exported build, which is exactly the trap `CLAUDE.md` already
  warns about.
- The web build deploys to **Vercel**, with GitHub Pages as an opt-in backup
  behind the `ENABLE_PAGES` repository variable.
- `tests/smoke_test.gd` drives real input with `Input.action_press`, so the
  playtest scripts can use the same approach for anything that does not need a
  browser.
